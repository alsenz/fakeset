## The lower-cover problem

When two or more datasets include the same parent, they form that parent's **lower cover**.
Their rows must all come from the parent population, but how the rows are shared between
them is not obvious.

Consider three SME tiers that all include `organisations`:

```yaml
# small.yaml — includes organisations, ratio: 0.4
# medium.yaml — includes organisations, ratio: 0.35
# micro.yaml — includes organisations, ratio: 0.25
```

If the tiers are mutually exclusive (an organisation is exactly one size), their rows
partition the parent cleanly: segment A is small-only, segment B is medium-only,
segment C is micro-only.

But if two lower-cover members could overlap — e.g. `active_customers` (ratio 0.7)
and `premium_customers` (ratio 0.3) sharing the `customers` parent — then some
customers are both active *and* premium. The sizes of the four possible segments
(`active-only`, `premium-only`, `both`, `neither`) are not determined by the marginal
ratios alone.

fakeset handles both cases correctly via **Bernoulli factoring**.

## The three-step algorithm

`segment.rs::plan_segments` solves the joint distribution in three steps:

### Step 1 — Product-Bernoulli prior

For N lower-cover members, enumerate all 2^N possible membership subsets. Each
subset is a **segment** — rows belonging to exactly that combination of lower-cover
members.

The prior weight of each segment is the product of marginal in/out probabilities:

```
weight(S) = ∏ᵢ { ratio[i]   if member i ∈ S
                { 1−ratio[i] if member i ∉ S
```

This assumes all memberships are *independent* Bernoulli trials. For genuinely
independent flags (e.g. `is_active` and `has_premium`) this prior is exact. For
mutually exclusive categories, the prior assigns weight to impossible combinations
which are then pruned in step 2.

### Step 2 — Conflict pruning

Zero out any segment whose field constraints are mutually contradictory.
Two lower-cover members conflict when they each pin the same field to different
constant values:

```yaml
# small.yaml: employee_count.value: "small"
# medium.yaml: employee_count.value: "medium"
```

No organisation can be both small and medium, so the segment `{small, medium}` gets
weight zero. Its weight is redistributed proportionally to surviving segments.

### Step 3 — IPF (Iterative Proportional Fitting)

After pruning, the surviving segment weights generally no longer have the correct
marginals (each member's declared `ratio`). IPF rescales the weights iteratively
until the marginals are exactly restored. This typically converges in a few passes.

Integer row counts are derived by **largest-remainder (Hamilton) rounding**: every
segment is floored, then the leftover rows (`total − Σ floors`) are handed to the
segments with the largest fractional parts. This is unbiased *and* conserves the
parent total exactly — the latter matters when a member is also a parent, whose
in-group row count must match the count its own generation step produced.

## A concrete example

Three SME tiers: `small` (ratio 0.4), `medium` (ratio 0.35), `micro` (ratio 0.25).
All three pin `size_category` to different constants — so any segment containing
more than one tier is pruned.

The surviving segments are exactly the three single-tier segments plus the
`neither` remainder (ratio 0.0, since 0.4+0.35+0.25=1.0). With no remainder,
only three segments survive — identical to the original lower-cover elements.
This is the degenerate case where Bernoulli factoring reduces to a simple partition.

For a non-degenerate case, consider `active_customers` (ratio 0.7) and
`premium_customers` (ratio 0.3) with no conflicting field constraints:

| Segment | Prior weight | After IPF |
|---------|-------------|-----------|
| active-only | 0.7 × 0.7 = 0.49 | 49 rows |
| premium-only | 0.3 × 0.3 = 0.09 | 9 rows |
| both | 0.7 × 0.3 = 0.21 | 21 rows |
| neither | 0.3 × 0.7 = 0.21 | 21 rows |

Marginals check: active-only + both = 49 + 21 = 70 ✓, premium-only + both = 9 + 21 = 30 ✓.

## All lower-cover members participate

Every lower-cover member participates in segmentation — even those with `ratio: 1.0`.
A member with `ratio: 1.0` contributes its field constraints to conflict pruning even
though it never appears in a "not in this member" segment.

## Recursive factoring

Bernoulli factoring is applied recursively bottom-up. If `employees` has a lower
cover of `{remote, on-site}`, and both `employees` and `seniors` are in the lower
cover of `people`, factoring proceeds:

1. Expand `employees` lower cover first → creates `remote/emp`, `on-site/emp`
   segment atoms.
2. Expand `people` lower cover `{employees, seniors}` → segments that each
   incorporate the already-expanded `employees` sub-atoms.

## The segment cap

The hard cap is **1,000,000 feasible segments** (`MAX_FEASIBLE_SEGMENTS`). Unlike a
member-count cap, this bounds the number of *surviving* segments — not the raw 2^N
enumeration space. In practice, conflict pruning reduces the feasible set to a
small fraction of 2^N (often just N+1 singletons for mutually-exclusive groups),
so groups with many more than 16 members are handled correctly as long as their
feasible segments stay below the cap.

<Aside type="note">
There is no `--max-lower-cover` flag. The branch-and-bound enumeration (see below)
makes a member-count cap unnecessary: the work is proportional to the number of
*surviving* feasible segments K, not to 2^N.
</Aside>

## Implementation: branch-and-bound DFS

`segment.rs::plan_segments` avoids touching all 2^N subsets by using a
**branch-and-bound depth-first search** over the inclusion lattice:

### Step 1 — Precompute pairwise conflict masks

Before the DFS, `precompute_conflicts` builds a per-member `conflict_masks`: for
member `i`, `conflict_masks[i]` is the set of all members `j` whose constraints
conflict with member `i`. Each mask is a `FixedBitSet` (so there is no ceiling on the
number of members in a group). This requires only N×(N−1)/2 `try_merge_incremental`
checks — one per pair — and is O(N²) overall.

### Step 2 — Branch-and-bound DFS

`enumerate_segments_dfs` walks an **entry plan** recursively. Each entry is either a
plain lower-cover member or an **exclusion group** (a lowered
[tagged union](/concepts/variant-lowering/) — its cases are mutually exclusive):

- **Plain member** — two branches: *exclude* (multiply weight by `1 − ratio`) and
  *include* (check `mask.is_disjoint(&conflict_masks[i])`, then `try_merge_incremental`;
  on success multiply by `ratio` and recurse with member `i` added to the mask).
- **Exclusion group** — `N + 1` categorical branches: *no case* (weight `1 − Σvᵢ`,
  pruned when that is 0 — a mandatory union) and one branch per case (weight `vᵢ`).
  Because the search picks at most one case, two cases of a union can never co-occur
  in a segment — mutual exclusion is structural, needing no constraint or column.

Entire subtrees are pruned immediately when a conflict is detected — no work is
done for infeasible descendants. For one-of groups (mutually exclusive members),
every joint branch is pruned, reducing the feasible set to exactly N+1 entries.

Constraint merging is incremental: each recursive call extends the *parent call's*
already-merged `HashMap<String, FieldConstraints>` by one new member. The expensive
per-field merge is paid at most once per member per path through the DFS, not once
per 2^N mask.

The DFS halts with an error if `K > MAX_FEASIBLE_SEGMENTS` (1,000,000).

### Step 3 — Sparse IPF and Bernoulli rounding

`ipf_rescale_sparse` iterates only the K feasible segments (stored as
`HashMap<FixedBitSet, f64>` of membership mask → weight). Each pass is O(K·N). For
one-of groups, K = N+1, making this thousands of times faster than dense O(2^N·N) IPF.
IPF only runs when conflict pruning actually removed mass; with no conflicts the
prior weights are already exact and IPF is skipped.

Integer row counts are derived by largest-remainder (Hamilton) rounding: floor every
segment, then award the leftover rows to the largest fractional parts — unbiased and
exactly total-conserving.

### Summary

| Phase | Cost | Best case |
|-------|------|-----------|
| Pairwise conflict precompute | O(N²) | Amortised once per group |
| Branch-and-bound DFS | O(K·N) | One-of groups: K = N+1 |
| Sparse IPF | O(K·N) per round | Always proportional to K |

The work is proportional to K — the number of feasible segments — rather than 2^N.

## Further scaling directions

The current implementation handles arbitrarily large lower-cover groups efficiently
when K is small. Two known directions remain for adversarial cases:

- **Higher-arity conflict detection.** The current precomputation checks pairs. A
  triple (A, B, C) can be jointly infeasible without any pair being infeasible
  (e.g. overlapping numeric ranges that only become empty when all three are
  intersected). Extending to k-ary conflict checks would prune more branches in
  the DFS at the cost of O(N^k) preprocessing.

- **Independent group decomposition.** If the lower-cover members can be partitioned
  into two subsets that share no constrained fields, their joint distribution
  factors exactly — 2^(N/2) × 2^(N/2) = 2^N subsets collapse to 2·2^(N/2). A
  graph-connectivity check on the shared-field graph before enumeration would
  expose this structure and allow the two halves to be factored independently.
