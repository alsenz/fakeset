## Dataset (top level)

Every YAML file defines one `SyntheticDataset`.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | ✓ | Dataset name; used as the default output filename. |
| `format` | [`Format`](#format) | ✓ | Output format: `parquet`, `csv`, `json`, or `jsonl`. |
| `rows` | integer | — | Explicit row count. Mutually exclusive with `ratio` on `include`. |
| `locale` | [`Locale`](#locale) | — | Default locale for locale-capable generators. Field-level `locale` takes precedence. |
| `output` | string \| [`Output`](#output) | — | Output file: plain path string or `Output` block. Sugar for a single-entry `outputs` list. Accepts `output_file` as an alias. |
| `outputs` | [`Output[]`](#output) | — | Multiple output files (e.g. one clean, one degraded). If both `output` and `outputs` are set, `outputs` wins. |
| `include` | [`Include`](#include) | — | Declares this dataset as a constrained subset of another. |
| `import` | [`ImportSpec`](#import) | — | Load rows from a pre-existing external file instead of generating them. Mutually exclusive with `rows`. |
| `links` | [`Include[]`](#include) | — | Linked datasets for list-link sampling. Each entry names a dataset from which list items are drawn. |
| `data` | [`Field[]`](#field) | — | Field definitions. Evaluated in declaration order for expressions. |
| `variants` | [`VariantSchema[]`](#variantschema) | — | When non-empty, virtually splits the dataset into N concrete variants. Each variant inherits `data` fields and overrides/extends them. |

### Example

```yaml
name: policies
format: parquet
rows: 10000
locale: en
output: policies.parquet      # plain string — shorthand for Output { file: policies.parquet }
data:
  - name: policy_id
    type: string
    generator: uuid
```

## Output

Describes one output file for a dataset. When `output:` is set to a plain string, it is shorthand for `Output { file: <string> }` with no quality stanza.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `file` | string | ✓ | Output file path (relative to the `--output` directory). May include an extension; if the extension matches the dataset `format`, it is used as-is, otherwise the format extension is appended. |
| `quality` | [`DataQuality`](#dataquality) | — | Data-quality degradation applied after the clean batch is finalised. |

### Examples

```yaml
# Single output — shorthand string form (no quality)
output: customers.parquet

# Single output — block form with DQ
output:
  file: customers_dirty.parquet
  quality:
    nulls: 0.05
    corruptions:
      truncation: 0.1

# Multiple outputs — clean + degraded from the same generated batch
outputs:
  - file: customers_clean.parquet
  - file: customers_dirty.parquet
    quality:
      duplication: 0.05
      missing: 0.02
      nulls: 0.05
      corruptions:
        character_deletion: 0.02
        truncation: 0.05
        noise: 0.1
```

## DataQuality

Controls synthetic data degradation applied to an output file **after** the clean batch is finalised. The clean batch used by the include lattice, witness generation, and `AccumulateToLinked` is never touched.

All probability fields are **independent Bernoulli rates**: each eligible cell fires independently at the stated probability.

Transforms are applied in order: duplication → missing rows → per-column (nulls → defaults → corruptions).

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `duplication` | float 0–1 | — | **Output-level only.** Fraction of rows to duplicate. Each selected row is appended once as an exact copy. Applied first. |
| `missing` | float 0–1 | — | **Output-level only.** Fraction of rows to delete (applied after duplication). |
| `nulls` | float 0–1 | — | Per-cell probability of replacing the value with null. |
| `default_rate` | float 0–1 | — | Per-cell probability of replacing the value with a type-appropriate default (see default value table below). |
| `corruptions` | [`Corruptions`](#corruptions) | — | Per-mode corruption probabilities. |
| `default_values` | any[] | — | **Field-level only.** Custom default values to draw from when `default_rate` fires. Must be compatible with the field type. |
| `defaults_mode` | [`DefaultsMode`](#defaultsmode) | — | **Field-level only.** Whether `default_values` replaces or extends the built-in set. Default: `extend`. |

#### Built-in default values

| Type | Defaults |
|------|----------|
| `string` | `""`, `"N/A"`, `"NA"`, `"None"`, `"NULL"`, `"n/a"` |
| `number` | `0`, `0.0` |
| `boolean` | `false` |
| `date` | `1970-01-01`, `1900-01-01`, `9999-12-31` |
| `date_time` | `1970-01-01T00:00:00Z` |
| `object`, `list` | *(no-op — `default_rate` is silently ignored)* |

## Corruptions

Sub-object controlling per-mode corruption probabilities. Each sub-field is an independent per-cell Bernoulli rate. At the **dataset level**, inapplicable modes (e.g. `noise` on a string column) are silently skipped. At the **field level**, inapplicable modes are a validation error.

| Field | Type | Applies to | Description |
|-------|------|-----------|-------------|
| `character_deletion` | float 0–1 | string | Delete one random character. |
| `character_insertion` | float 0–1 | string | Insert one random ASCII character at a random position. |
| `truncation` | float 0–1 | string | Truncate to a random prefix length. Models VARCHAR overflow — a particularly common real-world corruption. |
| `encoding` | float 0–1 | string | Introduce an encoding corruption via a lossy Latin-1 round-trip, producing mojibake. |
| `noise` | float 0–1 | number | Add Gaussian noise. Amplitude = `noise_scale × σ` where σ is the column's empirical std dev over the clean batch. If the column is constant (σ = 0), `noise_scale` is used directly as the amplitude. |
| `noise_scale` | float | number | Multiplier on the column std dev for noise amplitude. Default: `1.0`. Not a probability. |
| `day_shift` | float 0–1 | date, date_time | Shift the value by a random number of days drawn uniformly from `[−day_shift_max, +day_shift_max]`. |
| `day_shift_max` | integer | date, date_time | Maximum absolute shift in days. Default: `30`. Not a probability. |

### Example

```yaml
quality:
  duplication: 0.03
  missing: 0.01
  nulls: 0.04
  default_rate: 0.02
  corruptions:
    character_deletion: 0.01
    character_insertion: 0.01
    truncation: 0.05
    encoding: 0.005
    noise: 0.08
    noise_scale: 0.5
    day_shift: 0.05
    day_shift_max: 90
```

Controls whether field-level `default_values` replaces or augments the built-in default set.

| Value | Description |
|-------|-------------|
| `override` | `default_values` replaces the built-in defaults entirely. |
| `extend` | `default_values` is merged with the built-in defaults. **Default.** |

## import

Declares that this dataset's rows come from a pre-existing external file instead of being
generated from scratch. Mutually exclusive with `rows:`.

Supported formats: **Parquet**, **CSV**, **JSON array**, **JSONL**.

Imported columns are merged into the dataset schema before planning. Synthetic `data:`
fields are generated per-row and appended alongside the imported columns. Children-by-inclusion
may not specialise or `ref:` imported columns — see
[Specialisation restrictions](/concepts/execution-pipeline#import-specialisation-restrictions).

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `file` | string | ✓ | Path to the imported file, relative to the schema root. |
| `ref` | string | ✓ | Reference namespace for imported columns in `expression:` fields (e.g. `ref: tickers` → `tickers.symbol`). |
| `fields` | string\[\] | — | Column names to project in. `["*"]` or absent = all columns. |
| `exclude` | string\[\] | — | Column names to suppress after projection. Most useful with `["*"]`. |
| `ring` | [`RingBounds`](#ringbounds) | — | Hash ring bounds restricting which rows of the file are used. Assigned automatically by the planner for datasets with a lower cover; set manually to use a fixed fraction of the file. |

### RingBounds

Hash ring bounds `[start, end)` over `[0.0, 1.0)`. Row `i` of the imported file is
included iff `h(i) ∈ [start, end)` where `h` is a deterministic positional hash seeded
by `--seed.ring`.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `start` | float | ✓ | Ring start (inclusive). Must satisfy `0.0 ≤ start < end`. |
| `end` | float | ✓ | Ring end (exclusive). Must satisfy `start < end ≤ 1.0`. |

### Example

```yaml
name: stocks
format: parquet
output_file: stocks
import:
  file: data/tickers.parquet
  ref: tickers
  fields: ["symbol", "name", "sector"]
  ring:             # optional: restrict to the first 50% of the file
    start: 0.0
    end: 0.5
data:
  - name: score
    type: number
    range: { min: 0.0, max: 100.0 }
  - name: label
    type: string
    expression: "CONCAT(tickers.symbol, ' — ', tickers.sector)"
```

The typical pattern for using an imported file as a **sampling pool without writing it to disk**:

```yaml
# tickers.yaml — imported pool, not written to disk (no output_file)
name: tickers
format: parquet
import:
  file: data/tickers.csv
  ref: tickers

# trades.yaml — purely synthetic; draws ticker metadata from the pool
name: trades
format: jsonl
output_file: trades
rows: 10000
links:
  - file: tickers.yaml
    ref: tickers
    cardinality: { min: 1, max: 3 }
data:
  - name: trade_id
    type: string
    generator: uuid
  - name: instruments
    type: list
    content:
      from: tickers
      fields:
        - name: symbol
          ref: tickers.symbol
```

## Include

Used in both `include:` (top-level constraint inclusion) and `links:` (list-link declarations).

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `file` | string | ✓ | Path to the included YAML file, relative to this file. |
| `ref` | string | ✓ | Name used to reference fields from this include: `ref: <ref>.<field>`. |
| `ratio` | float | — | Marginal row-membership probability (0.0–1.0). In `include:` this drives the child's row count from the parent: `parent_rows × ratio`. In `links:` this limits the fraction of linked-dataset rows eligible for sampling. |
| `cardinality` | [`CountSpec`](#countspec) | — | **`links:` only.** How many items to draw per outer row. |
| `reinforcement` | float | — | **`links:` only.** Intra-list sampling intensity: `0` = without-replacement (each linked row drawn at most once per outer row); `1` or absent = uniform with-replacement (default); `> 1` = Pólya-urn clumping (previously-drawn rows become progressively more likely within the same list). Values in the open interval `(0, 1)` are invalid. `reinforcement` applies Pólya sampling within the partition defined by `overlap`. |
| `overlap` | float | — | **`links:` only.** Cross-list sampling scope: `0` = non-overlapping (each staging row draws from an exclusive index-based shard of the eligible linked pool, so the same linked row cannot appear in two different outer rows' lists); `1` or absent = unrestricted (all staging rows draw from the full eligible pool, default); `> 1` = power-law popularity bias (lower-indexed linked rows are progressively more probable across all staging rows, producing cross-list clumping). Values in the open interval `(0, 1)` are invalid. |
| `fields` | string[] | — | Field names to automatically copy into this dataset as `ref: <ref>.<field>` entries. Use `["*"]` for all fields. |
| `exclude` | string[] | — | Field names to suppress after `fields` expansion. Only valid when `fields` is non-empty. |

<Aside type="tip">
`ratio` and `rows` are mutually exclusive on the same dataset. Use `ratio` when
the child's size should be derived from the parent; use `rows` for root datasets
with a fixed count.
</Aside>

<Aside type="caution">
**`overlap: 0` and row ordering.** When `overlap: 0`, shards are assigned by index position
in the eligible linked-row prefix (determined by `ratio`). If the linked dataset has a
non-random internal row ordering — for example because it was written in sorted order or
because only the first N rows pass a `ratio` filter applied to a structured file — adjacent
shards may be compositionally similar, reducing the effective independence between outer rows.
To mitigate this, ensure the linked dataset is generated with randomised row order (fakeset
output is unordered by default) or explicitly shuffle it before use. This is a property of
index-based partitioning, not unique to `overlap`.
</Aside>

### Example

```yaml
include:
  file: customers.yaml
  ref: customers
  ratio: 0.1
  fields: ["*"]            # copy all customer fields as refs
  exclude: [internal_notes]
```

## Field

Defines one column in a dataset's schema.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | ✓ | Column name in the output file. |
| `type` | [`FieldType`](#fieldtype) | — | Column type. Required unless `ref` is set (type is then inherited from the ref target). |
| `ref` / `refs` | [`RefsSpec`](#refsspec) | — | Cross-dataset field reference. `ref: <ref>.<field>` for a single ref; `refs:` for multiple including collect bindings. |
| `generator` | [`Generator`](#generator) | — | Specific fake-rs generator to use. When absent, the type default is used. |
| `locale` | [`Locale`](#locale) | — | Locale for this field's generator. Overrides the dataset-level locale. |
| `range` | [`Range`](#range) | — | Inclusive numeric bounds for `number` fields. |
| `value` | any | — | Emit this constant for every row. Incompatible with `generator`, `range`. |
| `fields` | [`Field[]`](#field) | — | Nested fields for `object` type. |
| `content` | [`ListContent`](#listcontent) | — | Element spec for `list` type. |
| `variants` | [`FieldVariant[]`](#fieldvariant) | — | Alternatives for `type: variant` fields. |
| `parquet` | [`ParquetConfig`](#parquetconfig) | — | Arrow/Parquet type override. Overrides the default Arrow type inferred from `type`. |
| `expression` | string | — | SQL expression evaluated after all other fields are generated. Must reference only fields declared above this one. Mutually exclusive with `type`, `ref`, `generator`, `range`, `value`. |
| `hidden` | boolean | — | Present in the internal batch but excluded from output. Set automatically for expression dependency pull-down. |
| `count` | [`CountSpec`](#countspec) | — | Items per row for `list` fields. Ignored on other types. |
| `precision` | integer | — | Decimal precision for `number` fields. Positive = decimal places; negative = rounds by powers of 10 (e.g. `-2` rounds to the nearest 100). |
| `default` | any | — | Fallback value when no child provides an inherited value. List collect targets use `default: []`. |
| `quality` | [`DataQuality`](#dataquality) | — | Per-field data-quality overrides. Only valid when the dataset's output block also declares a `quality` stanza. |
| `after` | string | — | Lower bound for `date` / `date_time` generation. `YYYY-MM-DD` for `date`; RFC 3339 for `date_time`. Must precede `before` when both are set. |
| `before` | string | — | Upper bound for `date` / `date_time` generation. See `after`. |
| `args` | map | — | Generator-specific arguments. See the [generator args table](#generator-args) below. |

### Examples

```yaml
# Simple typed field
- name: price
  type: number
  range: { min: 0.01, max: 999.99 }
  precision: 2

# Constant value
- name: status
  type: string
  value: "active"

# Ref field (inherits type from target)
- name: customer_id
  ref: customers.customer_id

# Expression field
- name: vat_amount
  expression: "price * 0.2"

# Date field with bounded range
- name: created_at
  type: date
  after: "2020-01-01"
  before: "2025-12-31"

# Weighted boolean (80% true)
- name: is_active
  type: boolean
  args: { ratio: 80 }

# Object field
- name: address
  type: object
  fields:
    - name: street
      type: string
      generator: street_name
    - name: city
      type: string
      generator: city_name

# Variant field (a tagged union: exactly one case per row)
- name: tier
  type: variant
  variants:
    - value: "gold"
      ratio: 0.1
    - value: "silver"
      ratio: 0.3
    - value: "bronze"        # no ratio → takes the remainder (0.6)
```

A `type: variant` field is a **tagged union** — each row takes exactly one case.
On a dataset that includes another, the cases are *lowered* into the lattice and
distributed by the same segmentation as lower-cover members, so the declared
`ratio`s are honoured. See [Variants as Tagged Unions](/concepts/variant-lowering/).

### Generator args

Some generators accept an `args` map to control their output. Unknown keys are validation errors.

| Generator | Key | Type | Default | Description |
|-----------|-----|------|---------|-------------|
| `sentence` | `min` | integer | 5 | Minimum word count. |
| `sentence` | `max` | integer | 10 | Maximum word count. |
| `paragraph` | `min` | integer | 3 | Minimum sentence count. |
| `paragraph` | `max` | integer | 6 | Maximum sentence count. |
| `words` | `min` | integer | 3 | Minimum word count. |
| `words` | `max` | integer | 8 | Maximum word count. |
| `sentences` | `min` | integer | 2 | Minimum sentence count. |
| `sentences` | `max` | integer | 5 | Maximum sentence count. |
| `paragraphs` | `min` | integer | 2 | Minimum paragraph count. |
| `paragraphs` | `max` | integer | 4 | Maximum paragraph count. |
| `password` | `min` | integer | 8 | Minimum password length (characters). |
| `password` | `max` | integer | 20 | Maximum password length (characters). |
| `geohash` | `precision` | integer 1–12 | 6 | Geohash precision level. |
| `number_with_format` | `format` | string | — | **Required.** Format pattern: `#` = random digit, `^` = random digit 1–9. Example: `"###-###"`. |
| `boolean` *(no generator required)* | `ratio` | integer 0–100 | 50 | Percentage of rows that are `true`. |

```yaml
# Short password
- name: pin
  type: string
  generator: password
  args: { min: 4, max: 6 }

# Formatted account number
- name: account_number
  type: string
  generator: number_with_format
  args: { format: "####-####-####" }

# Brief paragraph (2–3 sentences)
- name: notes
  type: string
  generator: paragraph
  args: { min: 2, max: 3 }
```

## ListContent

Specifies the element type for a `list` field.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `from` | string | — | When set, names the link ref (from `links:`) from which items are drawn. Activates the witness/assembly pipeline. |
| `project` | string | — | Project a single field from the linked dataset, producing a scalar list. Value: `"<link_ref>.<field_name>"`. Mutually exclusive with explicit `fields` in the item spec. |
| *(item fields)* | *(Field fields)* | — | All `Field` properties apply to the list item spec (`type`, `generator`, `fields`, etc.). When `from:` is set, `fields:` describes the struct fields of each list item. |

### Example — scalar list

```yaml
- name: tags
  type: list
  count: { min: 1, max: 5 }
  content:
    type: string
    generator: word
```

### Example — list-link field

```yaml
- name: directors
  type: list
  content:
    from: individual
    fields:
      - name: name
        refs: [ individual.full_name ]
      - name: role
        type: string
        value: "director"
      - name: employer
        type: string
        refs: [ company_name ]   # outer-scoped ref
```

## RefsSpec

Specifies one or more ref bindings on a field. Two forms are accepted:

**Single ref** — shorthand for one type-sourcing ref:

```yaml
ref: customers.customer_id
```

**Multi ref** — list of ref entries, enabling collect bindings:

```yaml
refs:
  - customers.customer_id        # simple entry
  - target: cats.id              # rich entry: type-sourcing ref
  - bind: cats.owner_ids         # rich entry: collect binding
    reducer: collect
```

Each entry in a multi-ref list is either a plain string (simple ref) or an object
with optional `target:`, `bind:`, and `reducer:` keys.

| Field | Type | Description |
|-------|------|-------------|
| `target` | string | The ref target (`"<ref>.<field>"`). Absent on bind-only entries. |
| `bind` | string | The collect target (`"<ref>.<field>"`). Used with `reducer:`. |
| `reducer` | [`Reducer`](#reducer) | How values are assembled when the referenced include has different cardinality. |

---

## CountSpec

Specifies a count — used for `count:` (list items per row) and `cardinality:` (linked-dataset draws per outer row).

Three forms:

```yaml
count: 5                          # fixed
count: { min: 2, max: 8 }        # uniform random integer in [min, max]
count: { mean: 5.0, std_dev: 2.0 } # normal distribution, rounded and clamped ≥ 0
```

---

## Range

Inclusive numeric bounds for `number` type fields.

```yaml
range:
  min: 0.0    # optional lower bound
  max: 100.0  # optional upper bound
```

Either bound may be omitted; if both are absent, the generator produces an
unbounded float64.

## Reducer

Controls how values are assembled when a ref spans a cardinality boundary (e.g. accumulating child values into a parent field, or collecting linked-dataset values into the outer dataset).

| Value | Description |
|-------|-------------|

| `sum` | Sum numeric values. |
| `max` | Maximum value. |
| `min` | Minimum value. |
| `collect` | Gather all values as a list. |
